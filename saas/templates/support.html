Troubleshooting

GitHub Authentication Failed

Error: "GitHub authentication failed" or "Invalid state parameter"

Solutions:

  • Ensure you have a valid GitHub account
  • Check that cookies are enabled in your browser
  • Clear your browser cache and cookies, then try again
  • Try in incognito/private mode to eliminate browser extensions
  • Ensure your GitHub account hasn't been temporarily restricted
  • Verify your internet connection is stable

Still not working? Contact support

Repository Scan Fails

Error: "Scan failed" or "Repository clone failed"

Common Causes and Solutions:

  • No Access: Verify you have access to the repository on GitHub. Public repositories require no special permissions; private repositories require authorization.
  • Network Error: Check your internet connection. Try again after a few seconds.
  • Repository Too Large: Very large repositories (>1GB) may take longer or fail. Try a smaller repository first.
  • Permission Issue: Ensure GitHub OAuth token has repository access permission. Try logging out and logging back in.
  • Server Issue: If problem persists, GVD servers may be experiencing issues. Try again later.

Still not working? Contact support

Scan Takes Too Long

Reason: Scan time depends on repository size and complexity.

  • Small repositories (<10MB): Usually <30 seconds
  • Medium repositories (10-100MB): Usually 1-5 minutes
  • Large repositories (>100MB): Can take 10+ minutes

Tips to Speed Up Scans:

  • Scan during off-peak hours when servers aren't busy
  • Close other browser tabs to free up system resources
  • Use a stable, high-speed internet connection
  • Scan public repositories (faster than private)

Options:

  • You can stop the scan anytime and try again later
  • Large repositories may need to be scanned in segments

Can't Find My Repository

Solutions:

  • Check Access: Verify the repository is accessible from your GitHub account. You must own it or be a collaborator.
  • Filter Settings: Ensure you're not filtering by visibility. Try "All Repositories" filter.
  • Search: Use the search box to search by repository name.
  • Pagination: Click "See more" to load additional repositories.
  • Refresh: Log out and log back in to refresh your repository list.
  • Archived Repos: Archived repositories may not appear in the list.

Notifications Aren't Working

Solutions:

  • Check that JavaScript is enabled in your browser
  • Ensure browser notifications haven't been blocked for this site
  • Try refreshing the page
  • Look for the notification bell icon (🔔) in the top navigation - click it to see pending notifications
  • Try in incognito/private mode to test without extensions
  • Check your browser's console (F12 Developer Tools) for JavaScript errors

Session Expired - Need to Log In Again

Why this happens: GVD sessions automatically expire after 24 hours of inactivity for security.

Solution: Simply log in again using "Continue with GitHub"

Note: All temporary data (scan reports, notifications) are cleared when your session expires. This is by design for privacy protection.

Reports Won't Download

Solutions:

  • Verify your browser allows downloads from this site
  • Check your browser's download folder - file may already be downloaded
  • Try a different browser (Chrome, Firefox, Safari, Edge)
  • Try downloading the JSON report (it's lighter weight than PDF)
  • Check that your internet connection is stable
  • Disable browser extensions that might interfere with downloads

Finding More Vulnerabilities Than Expected

Why this happens: GVD performs comprehensive security scanning and may detect:

  • Secrets in git history (even if deleted from current version)
  • Credentials in comments and documentation
  • Test/dummy credentials that look real
  • Patterns similar to real secrets but not actually sensitive

Next Steps:

  • Review each finding carefully
  • Check if credentials have already been rotated
  • Clean git history if secrets are present in commits
  • Use .gitignore to prevent future commits of sensitive files

Frequently Asked Questions

Is GVD free?

Yes, GVD is completely free. You only need a GitHub account to get started.

Does GVD upload my code to its servers?

No. GVD uses a local-first approach. Your code is cloned locally, scanned locally, and then deleted. Only the security report is retained temporarily in your session.

How long are my scan results kept?

Scan results are stored in your session while you're logged in. When you log out or your session expires (24 hours), all results are automatically deleted.

Can I scan private repositories?

Yes. GVD can scan any repository you have access to on GitHub, including private repositories.

How do I revoke GVD's access?

Go to GitHub Settings → Connected applications, find GVD, and click "Revoke".

What information does GVD collect from me?

GVD collects your GitHub profile information (username, email, avatar) and your GitHub access token. See our Privacy Policy for complete details.

Can I schedule automatic scans?

Currently, scans are manual. You initiate scans individually or use the bulk scan feature to scan all repositories at once.

Is GVD accurate? Will it find all vulnerabilities?

GVD uses pattern-based detection for known secret formats. No scanning tool is 100% effective - it may miss some vulnerabilities and have false positives. Always conduct additional security reviews.

Can I share scan reports with my team?

Yes. After a scan completes, download the JSON or PDF report and share it with team members. However, note that reports are session-based and may not be available after logout.

What if I find a false positive?

Review the finding carefully. If it's truly a false positive (not actually a security risk), you can dismiss it from the report or note it for your team.

Is GVD GDPR compliant?

Yes. GVD complies with GDPR and other privacy regulations. See our Privacy Policy for details.

What are the severity levels?

  • Critical: Immediate threat (e.g., exposed database credentials)
  • High: Serious issue (e.g., exposed API keys)
  • Medium: Moderate concern (e.g., weak credentials)
  • Low: Low priority (e.g., configuration issues)
