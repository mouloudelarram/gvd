GVD Documentation

Welcome to GVD (GitHub Vulnerability Detector). This guide covers how to use the platform to scan your GitHub repositories for security vulnerabilities.

What is GVD?

GVD is a security-first GitHub integration that scans your repositories for secrets, sensitive files, and security risks. Using a local-first approach, your repository code never leaves your environment—only security reports are generated and shared with you.

  • Local-First: Repositories are scanned on your local machine. Code never leaves your environment.
  • Comprehensive: Detects secrets, API keys, tokens, and security configuration issues.
  • Session-Based: Results are stored temporarily during your session and automatically cleared on logout.
  • GitHub Integrated: Seamless login with your GitHub account and automatic repository discovery.

Getting Started

Step 1: Create Your Account

Visit GVD and click "Continue with GitHub" to sign up.

  • You'll be redirected to GitHub's authorization page
  • Review the requested permissions (repository access, user profile)
  • Click "Authorize" to grant access
  • You'll be redirected back to GVD and logged in

Step 2: Explore Your Dashboard

After logging in, you'll see your GitHub repositories displayed in a grid.

  • Each card shows repository name, visibility status, and description
  • Use search to find specific repositories
  • Filter by public/private repositories
  • Scroll to load more repositories ("See more" button)

Step 3: Initiate a Scan

Click the "Scan" button on any repository to begin scanning.

  • The repository will be cloned and analyzed locally
  • A progress indicator shows scan status
  • Results appear once the scan completes

Authentication

GitHub OAuth Login

GVD uses GitHub OAuth for secure authentication. This means you sign in using your existing GitHub account without sharing your password with GVD.

What Permissions Does GVD Request?

  • repo: Access to your repositories (needed to clone and scan)
  • read:user: Access to your profile information (name, email)

These permissions are required to discover and scan your repositories. GVD does not require write access.

Session Management

  • Your session is stored securely in a browser cookie
  • The session includes your GitHub access token (securely stored server-side)
  • Sessions automatically expire after 24 hours
  • Clicking "Logout" immediately clears your session and all temporary data

Revoking Access

You can revoke GVD's access to your GitHub account at any time through your GitHub settings:

  • Go to GitHub Settings → Connected applications
  • Find "GVD" in the list
  • Click "Revoke" to remove access

Repository Overview

  • Name: The repository name
  • Visibility: Badge indicating Public or Private
  • Description: Repository description from GitHub
  • Scan Button: Initiate a vulnerability scan

Search by Repository Name

Use the search box to find repositories by name. Search is performed as you type.

Filter by Visibility

  • All Repositories: Show all accessible repositories
  • Public: Show only public repositories
  • Private: Show only private repositories

Metrics

The top of the dashboard shows key metrics:

  • Total Repositories: Total number of accessible repositories
  • Public Repos: Number of public repositories
  • Private Repos: Number of private repositories

Scanning Repositories

Single Repository Scan

Click the "Scan" button on any repository to scan it individually.

  1. Clone: The repository is cloned to a temporary local directory
  2. Analyze: The local clone is scanned for vulnerabilities
  3. Report: A detailed security report is generated
  4. Display: Results are shown in the scan results modal

Bulk Scan

Click the "Scan All" button to scan all your repositories at once.

Bulk Scan Features

  • Real-time Progress: Watch the progress bar update as repositories are scanned
  • Live Statistics: See vulnerability counts by severity as scanning progresses
  • Live Logs: View scanning activity in real-time
  • Stop Option: Stop the bulk scan at any time
  • Summary Report: Comprehensive report of all findings once complete

What Does GVD Scan For?

Secrets and Credentials

  • API keys and tokens
  • AWS credentials and access keys
  • Database connection strings
  • Private SSH keys
  • OAuth tokens and secrets
  • Authentication tokens

Sensitive Files

  • .env files with sensitive configuration
  • Private key files (.pem, .key)
  • Configuration files with credentials
  • Backup files containing sensitive data

Git History

  • Secrets in commit messages
  • Secrets in previous file versions (even if deleted)
  • Historical configuration files with credentials

Severity Levels

GVD classifies findings into four severity levels:

🔴 Critical

Immediate security threat. Requires immediate action (e.g., exposed database credentials).

🟠 High

Serious security issue. Should be resolved promptly (e.g., exposed API keys).

🟡 Medium

Moderate security concern. Should be addressed (e.g., weak credentials in comments).

🟢 Low

Low-priority security issue. Can be addressed as part of regular maintenance.

Reports

Report Formats

GVD generates security reports in multiple formats:

JSON Report

A structured JSON document containing all findings, metadata, and analysis details. Perfect for programmatic access and integration with other tools.

Contains: Repository info, scan metadata, complete findings list, severity counts, recommendations

PDF Report

A professional, printable PDF report with organized findings, severity breakdown, and recommendations. Ideal for security reviews and documentation.

Contains: Executive summary, findings organized by severity, recommendations, scan details

Report Contents

  • Repository Information: Repository name, owner, URL, scan date/time
  • Summary Statistics: Total findings, breakdown by severity
  • Detailed Findings: Each finding includes location, type, severity, and recommendation
  • Remediation Advice: Suggestions for fixing each issue
  • Scan Metadata: Scan duration, repository size, scanning engine version

Downloading and Sharing Reports

After a scan completes, you can view and download reports directly from the results modal. Reports are stored temporarily in your session and are automatically deleted when you log out.

Privacy & Security

Local-First Architecture

GVD operates on a local-first principle: your repository code never leaves your machine. Here's how it works:

  1. You authorize GVD via GitHub OAuth
  2. You select a repository to scan
  3. GVD clones the repository to a temporary local directory on your machine
  4. The local clone is analyzed for vulnerabilities
  5. Only the security report is generated and stored (not the code)
  6. The temporary repository clone is deleted
  7. You view/download the report

Bottom line: Your repository code is never uploaded to GVD servers.

Session-Based Storage

All reports and scan results are stored temporarily in your session during login. Once you log out, all temporary data is automatically deleted:

  • Session reports are stored server-side in memory (not in a database)
  • No permanent database of your scans is maintained
  • Logging out immediately clears all session data
  • Sessions automatically expire after 24 hours

What Data Does GVD Store?

  • Your GitHub user profile (name, email, avatar)
  • Your GitHub access token (securely stored server-side)
  • Scan reports (temporary, session-based)

What GVD does NOT store:

  • Repository code or source files
  • Permanent scan history or results
  • Information about findings after you log out
  • Any data unrelated to scanning

Security Features

  • HTTPS Only: All communication is encrypted in transit
  • OAuth: Industry-standard authentication through GitHub
  • Session Security: Secure HTTP-only cookies with CSRF protection
  • Token Redaction: Sensitive tokens are redacted in logs
  • Input Validation: All user inputs are validated and sanitized

Frequently Asked Questions

Is my code uploaded to GVD?

No. GVD uses a local-first approach. Your code is cloned locally, scanned locally, and then the temporary clone is deleted. Only the security report is retained.

How long are my scan results stored?

Scan results are stored in your session while you're logged in. When you log out or your session expires (24 hours), all results are automatically deleted.

Can I scan private repositories?

Yes. GVD can scan any repository you have access to on GitHub, including private repositories. The required permissions are handled through GitHub OAuth.

What if a scan fails?

If a scan fails, you'll receive a notification with an error message. Common causes include network errors during cloning or insufficient permissions. See Troubleshooting for solutions.

How can I revoke GVD's access?

Go to GitHub Settings → Connected applications and click "Revoke" next to GVD.

Can I download my reports?

Yes. After a scan completes, click "Download JSON" or "Download PDF" to save the report to your computer.

Can I schedule automated scans?

Currently, scans are manual. You can initiate scans individually or use the bulk scan feature to scan all repositories at once.

How accurate are the findings?

GVD uses pattern-based detection for common secret formats. While the system is highly accurate for known patterns, no scanning tool is 100% perfect. Always review findings and treat them as guidance rather than definitive proof.

What if I find a false positive?

If a finding is incorrect, you can dismiss it from the report. GVD may learn from feedback to improve accuracy over time.

Is GVD free?

Yes, GVD is currently free to use. You only need a GitHub account to get started.

Troubleshooting

GitHub Authentication Fails

Solution:

  • Ensure you have a valid GitHub account
  • Check that your GitHub account has access to the repositories you want to scan
  • Clear your browser cookies and try again
  • Ensure JavaScript is enabled in your browser

Repository Scan Fails

Solutions:

  • Verify you have access to the repository on GitHub
  • Check your internet connection
  • Try scanning a smaller repository first
  • Wait a few minutes and try again (temporary network issue)

Scan Takes Too Long

Solutions:

  • Large repositories take longer to clone and scan. This is normal.
  • For repositories over 1GB, consider scanning public repositories instead
  • You can stop a slow scan and try again later

Notifications Don't Appear

Solutions:

  • Check that your browser hasn't blocked notifications
  • Ensure JavaScript is enabled
  • Try refreshing the page
  • Check the notification bell icon for pending notifications

Can't Find a Repository

Solutions:

  • Verify the repository is accessible from your GitHub account
  • Check the repository visibility (public vs private)
  • Use the filter to check "All Repositories"
  • Try searching by repository name
  • Log out and log back in to refresh your repository list

Session Expired

Solution:

Sessions automatically expire after 24 hours. Simply log in again to start a new session.
